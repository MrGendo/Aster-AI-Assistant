# 外部依赖接入规则

- 日期：2026-11-05，由用户反馈确立（vue-flow 三次返工的教训）

任何"学习 GitHub 项目来进化/加功能"的场景，动手前必须完成**文档研读关卡**：

1. **完整通读官方文档**（concepts / guides / API，不止 quickstart）——本次 vue-flow 的箭头颜色、Handle 规范都是文档明写的基础用法
2. **产出理解摘要**：优势 / 短板 / 约定与陷阱（进任务日志，作为集成方案的一部分）
3. **先方案后代码**：接入方案写清"用它的哪些规范用法"，再动手
4. **返工自查**：集成后如出现"文档里早写了"的问题，记入任务日志并回看第 1 步漏了什么

与平台自身流程的关系：这就是 PRD §5.6 证据分级对"接入方"的要求——评估别人项目时分五级证据，评估**自己要用的依赖**时同样不能停在"跑通了 quickstart"就当理解了。

适用排队项：gpt-researcher（候选#13，集成前先读透 docs.gpt-researcher.dev）、观察名单中的 langfuse / opencode / open-swe。
