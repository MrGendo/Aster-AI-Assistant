# 质量平台化三件套 · 完整流程

> 对应设计：`docs/superpowers/specs/2026-11-06-qa-platform-design.md` ｜ 全部机制均已实测跑通

## 总览：准入 → 过程 → 准出 → 沉淀 四层闭环

```
┌─ 方案准入 ─────────────────────────────────────────────┐
│ make_plan → validate_plan 硬校验（能力/引用/on_fail/    │
│ run_if 合法性）→ review_plan 检查单评审（LLM）           │
│   ├ 无问题 → 放行执行                                    │
│   └ 有问题 → 带问题清单重生成一次（仍过硬校验，增强不阻断）│
└────────────────────────────────────────────────────────┘
┌─ 过程质量（三层质量门，先于三件套已有）─────────────────┐
│ ① 结构校验：关键字段齐全才算数                           │
│ ② 步骤评审：llm_verify 按预设标准独立打分（无标准=计划拒收）│
│ ③ 交付终检：报告/调研/热点三类过"结论有据/来源可核验/无编造"│
│    未过 → 如实降级 partial，不伪装成功                   │
└────────────────────────────────────────────────────────┘
┌─ 回归准出（件一）──────────────────────────────────────┐
│ eval_cases 用例库 → 完整任务通道真实执行 → 双口径评分     │
│ 门禁：最近回归失败的能力禁止启用（409）                   │
│ 变更后自动回归：低于门槛自动回滚 + 通知                   │
└────────────────────────────────────────────────────────┘
┌─ 经验沉淀（件三）──────────────────────────────────────┐
│ 踩坑 → integration_lessons 入库 → LLM 转回归用例         │
│ → 下次变更被门禁自动守住（经验驱动 → 规则化）             │
└────────────────────────────────────────────────────────┘
         任务终态 → quality_json 结构化质量报告（件二）
```

## 件一：能力回归评测与准出门禁

### 数据模型（migration 0009）

```
eval_cases: id | capability('*'=全局) | name | goal(任务目标) | expect(验收标准)
            | enabled | last_result_json | finished_at | source(manual/lesson/replay_seed)
```

**用例三个来源**：replay_set 种子迁移（全局 3 条）、手工添加（API/UI）、教训沉淀（件三）。

### 执行流程（POST /api/eval/run {capability}）

1. 取该 capability 的启用用例（`'*'` 只在跑全局时执行）
2. **逐用例走完整任务通道**：create_task → execute（真实能力、真实 LLM、真实审批门禁——不是 mock，这是 Agent 回归与传统单测的本质区别）
3. `completed` = 通过，`partial/failed` = 未通过
4. 质量维度：replay_grade 能力（promptfoo llm-rubric）按每条 `expect` 评分——**完成率 ≠ 质量率双口径**（完成了但空洞也不合格）
5. 结果回写 `last_result_json`（含 task_id/status/passed/summary/graded）

实测数字：text_stats 2/2 完成；全局 4/4 完成、质量 2/4（llm-rubric 口径严格，完成率是门禁判据，质量率是参考信号）。

### 准出凭据 `regression_ok` 三态

| 状态 | 判定 | 结果 |
|---|---|---|
| 最近一次执行失败 | `last_result_json.passed=false` | **拦截**（409 带用例名） |
| 最近一次执行全过 | — | 放行 |
| 从未执行 | — | 免检放行 |

**两条规则的设计演进（面试重点，都是实测踩出来的）**：
- "从未执行也拦" + "凭据须晚于能力变更" 会形成**死锁**：停用→再启用循环里，能力停着用例永远跑不了；且启停本身触碰 `updated_at`，凭据即时过期。改为"规则只拦已证明的回归"。
- 真正的守护由三件事承担：apply 后自动回归、失败即拦、force 留痕。

### 门禁接线（两处）

**① 能力启用**（POST /api/capabilities/{name}/enable）：
```
回归失败 → 409「回归门禁未通过：用例「xx」最近一次未通过」
  ├─ 修复路径 A：POST /api/eval/run 重跑回归 → 凭据更新 → 放行
  └─ 修复路径 B：?force=1 人工越过 → tool_calls 审计留痕（gate_override, L1）
```

**② 进化提案应用后**（POST /api/proposals/{pid}/apply）：
```
apply 成功 → 后台自动跑全局回归
  ├─ 通过率 ≥ evo.regression_floor（默认 0.6）→ 结果记入提案实验记录
  └─ 低于门槛 → 自动回滚（snapshot 恢复）+ 铃铛通知   ← 风险闭环
```

### 上线首日的两个真实拦截（回归系统抓自己的缺陷）

1. **门禁死锁**：全局用例"对照-文本统计"因能力被停用而失败 → 失败凭据拦截一切启用 → 死锁。暴露规则缺陷 → 修规则。
2. **弱种子**：热点种子用 A/B/C 假素材 → 产出的报告被**自家交付终检**如实拦下（partial）→ 回归用例永远失败。暴露种子质量问题 → 换充实素材。

## 件二：方案质量评审 + 任务质量报告

### 计划评审（方案设计评审环节）

`review_plan` 在硬校验通过后、执行前介入，LLM 按四条检查单审计划：

1. 产出报告/结论/对外引用的步骤后是否都有 llm_verify 把关？
2. L1 风险步骤（联网/浏览）是否声明 fallback 或 on_fail？
3. 各步骤验收是否可判（desc/output_key 明确）？
4. 有无孤儿产出（关键产出没被下游使用）？

- 无问题 → 直接执行；有问题 → **带问题清单重生成一次**（仍过硬校验；重生成失败用原计划——评审是增强不是阻断）；token 计入任务预算。

### 任务质量报告（quality_json → 结果页质量卡）

三条执行路径（单能力/多步规划/报告）终态统一聚合：

| 路径 | 报告内容 |
|---|---|
| 单能力 | 结构校验 ✓/✗、交付终检 通过/未通过/未适用、证据来源数（+未过原因） |
| 多步规划 | 步骤数、每个 llm_verify 评审步结论、降级跳过步骤、是否发生过重规划 |
| 报告 | 长度校验、交付终检结论（+原因） |

前端质量卡直接渲染：`结构校验 ✓ 通过 ｜ 交付终检 · 未适用 ｜ 证据来源 0 条`。

## 件三：教训 → 回归用例沉淀

```
踩坑（如：辅助能力 404 无降级路径，fail-fast 拖死主链）
  → integration_lessons 入库（repo/stage_failed/reason）
  → POST /api/lessons/{id}/to_case
  → LLM 生成：goal（可用现有能力独立执行的任务目标）
             expect（验收标准）
  → eval_cases（source=lesson）→ 变更时被门禁自动守住
```

**真实案例**：教训#6（repo_quality 对未收录仓库 404 拖死主链）→ 生成用例"分析 pinia 仓库工程质量"，验收三条：①完成且不因辅助失败整体失败；②缺项明确标注"该维度信息不可用"；③过程走降级而非终止。**该用例已真实执行通过**——当年的坑现在是常驻守门员。

## 三件套联动：一条变更的完整旅程

```
能力变更提案 → 审批 → apply
  → 自动全局回归（真实执行所有全局用例）
     ├─ 达标 → 实验记录留档 → 能力可启用（门禁复核凭据）
     └─ 不达标 → 自动回滚 + 通知 ←──────────┐
                                            │
踩坑 → 教训入库 → 一键沉淀为回归用例 ─────────┘
（下一轮回归多一条守门员，防线随经验自动增厚）
```

## 快速索引（面试前 30 秒过一遍）

- 表：`eval_cases`（用例库）、`tasks.quality_json`（质量报告）
- API：`/api/eval/cases` CRUD、`/api/eval/run`、`/api/eval/gate/{cap}`（查凭据）、`/api/lessons`、`/api/lessons/{id}/to_case`、`/api/capabilities/{name}/enable?force=1`
- 设置：`evo.regression_floor`（回滚门槛，默认 0.6）
- 关键数字：回归 2/2 + 4/4（质量口径 2/4）、门禁 409→force 留痕→6/6 放行、教训→用例→执行通过、54 例离线测试
- 一句话：**完成率是门禁判据，质量率是改进信号；规则只拦已证明的回归，人工越过必须留痕**
