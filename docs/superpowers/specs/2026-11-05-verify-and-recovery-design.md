# 设计：验证评估节点 + 步骤失败策略与重规划（P0）

日期：2026-11-05 ｜ 状态：待批准

## 一、现状盘点（比预想厚，设计因此收窄）

- `llm_verify` 评审伪能力**已存在**（planner 契约含可选 verify 字段；_llm_verify 按标准独立打分，不通过即失败）——但规划器很少主动产出评审步，单能力路径完全无评审
- 步骤 `fallback` 接管链**已存在**（能力失败→依次试备用能力）
- 失败处理是 fail-fast：辅助步骤失败也整任务报废；无重试、无降级跳过、无重规划

**概念参照**（LangGraph graph-api 文档，读毕）：条件边=运行时函数决定去向；静态与动态路由混用是文档明示的反模式（我们 on_fail 属每步静态声明，不混用）；递归上限防循环（对应"每任务限重规划一次"）。

## 二、方案

### ① 验证评估节点（质量门）

- **A1 规划器契约强化**：产出"报告/综合/对外引用数据"的步骤后必须跟 llm_verify 评审步（criteria 从用户目标导出）——机制不动，只改 prompt 契约与校验
- **A2 交付终检**：单能力路径的 report / deep_research / hot_news 三类意图，交付前跑一次 _llm_verify（固定标准：结论有据可查、来源真实可核验、无编造）；通过 → completed，summary 尾注"✓ 已通过独立评审"；未通过 → **partial**（如实降级，不伪装成功）+ 理由可见。确定性能力（text_stats/repo_quality 等 L0）不验（零成本原则）
- **A3 呈现**：评审结论随 summary/error 展示，不新增表字段

### ② 失败策略 + 重规划（恢复力）

- **B1 步骤级 on_fail**（规划器契约新增，三选一）：
  - `abort`（默认，现行为）：失败终止任务
  - `skip`：辅助步骤降级——步骤标 `skipped`，计划继续；下游 `$N` 引用落"（上游输出缺失）"占位（既有机制，天然兼容）
  - `retry`：同能力重试一次（2 秒间隔），再败按 abort
- **B2 planner 指引**：富化/评分等辅助步骤标 skip；核心产出步骤默认 abort
- **B3 重规划（每任务限一次）**：abort 失败不再直接 _fail——带「目标 + 已完成步骤摘要 + 失败步骤与原因 + 未执行剩余步骤」调用 planner.replan 生成新剩余计划：已完成 outputs 保留复用，新步骤续 seq 追加入库；重规划失败或重规划后再次失败才最终 _fail。防循环：plan_json 记 replanned 标志
- **B4 状态**：task_steps 新增 `skipped` 状态文案；DAG/时间线渲染复用灰色
- 顺序：retry（若声明）→ fallback 链（既有）→ on_fail → abort 触发重规划（一次）

### 不做的

- run_if 条件步骤（P1，另案）
- 嵌套子规划（P2）
- 自治 agent loop（与门禁可审计的立身之本冲突，明确不做）

## 三、验证标准

1. 单测：on_fail 三路径、skip 后下游占位、重规划一次上限、终检意图触发表、未过终检→partial、planner 契约校验
2. 端到端实测：构造必然失败任务（仓库指向不存在 repo）真实触发重规划改道成功；一次报告任务真实通过交付终检
3. 既有 42 测试零回归
