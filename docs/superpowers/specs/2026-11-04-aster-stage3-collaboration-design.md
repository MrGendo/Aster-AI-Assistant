# Aster Stage 3 设计（多能力协作 · Spec）

- 日期：2026-11-04
- 需求输入：`product_requirement.md` §7（能力协作）、§8.4（组合经验）、§19 第三阶段
- 前置：Stage 2 已收口；已具备一次真实串联先例（news_fetch → hot_news_digest）
- 状态：**待用户批准执行**

## 1. 目标

把"单步模板调度"升级为"计划图调度"：主板按目标拆分多步任务，能力间传递结果，失败可接管，结果可复核——并且**协作必须可证明地比单能力好**（PRD §19 S3 验收原文），否则退回简单路径。

## 2. 核心设计

### 2.1 计划模型（DAG-lite）

```
task_steps 增加：output_key（本步产出的键名）、depends_on（依赖步的 seq 数组）
执行器：拓扑序调度——依赖齐备的步骤就绪；v1 并发=1（先求稳），就绪步按序执行
数据流：下游输入用 "$stepN.键名" 引用上游输出（占位符替换，最小实现）
```

- 规划器：LLM 读【目标 + 各 active 能力 descriptor】产出计划 JSON（步骤/能力/输入映射/输出键）；解析失败或计划非法 → 回退现有单步模板（绝不因规划失败而任务失败）
- 计划合法性硬校验：引用的能力必须 active、引用的步骤键必须存在、环检测——非法计划直接回退模板路径

### 2.2 协作模式落地（PRD §7.4 七种 → v1 四种）

| 模式 | 实现 | 后置 |
|---|---|---|
| 顺序 | depends_on 链 | — |
| 并行 | 无依赖步骤（v1 仍串行执行，仅语义标注；真并行 v2） | 真并发 |
| 失败接管 | 每步可配 fallback 能力列表，逐个降级 | — |
| 评审 | 专用 verify 步：LLM 按"验收标准"给 pass/fail+理由 | — |
| 候选比较 | — | v2 |
| 迭代改进 | — | v2（verify 失败带反馈重跑，上限 2 次） |
| 条件分支 | — | v2 |

### 2.3 交接信息（PRD §7.3）

每步执行时组装交接包：目标子句 + 上游引用数据 + 该能力 input_example 结构说明——LLM 规划时即生成"给这一步的输入模板"，执行期只做占位符替换，不让能力间互相猜格式。

### 2.4 经验与路由（§8.4 最小版）

- `capability_stats`（能力×结果统计：调用数/成功率/平均耗时），任务终态时更新
- 规划提示词携带各能力近期成功率——表现差的能力自然被规划器降权
- 组合经验：`integration_lessons` 复用，stage 字段记 "collab"，失败链路自动入库

### 2.5 安全（不变量）

- 每步照旧过网关（L1/L2 审批挂起整计划为 awaiting_user，批准后重试续跑——Stage 2.5 已实现该语义）
- 步数上限 6、递归深度 1（计划不得派生计划）、总超时 30 分钟——防协作失控（PRD §7.6）

## 3. 数据模型（迁移 0003）

```
task_steps: +output_key TEXT, +depends_on TEXT(JSON)
capability_stats(capability_id, calls, ok, avg_ms, updated_at)
```

## 4. UI 增量

任务详情：步骤树按依赖渲染（v1 缩进列表 + 依赖标注）；能力中心：成功率展示。

## 5. 验收（PRD §21 能力协作行 + §19 S3）

1. 拆分链演示：「分析 <仓库> 并把要点写成中文摘要」→ repo_analysis → LLM 摘要两步链，交接数据正确
2. 失败接管演示：禁用某上游能力后任务自动降级到 fallback 而非直接失败
3. 评审演示：verify 步拦下低质输出（构造样例），任务呈"验证中→失败/重试"而非伪装成功
4. 控制演示：审批挂起、步数上限、总超时三道闸各自生效
5. 对比证明：同一目标"单能力 vs 协作链"结果并排（人工评判协作增益）

## 6. 风险

| 风险 | 应对 |
|---|---|
| LLM 计划质量不稳 | 计划硬校验+模板回退；模板路径永不删除 |
| 占位符数据流表达力不足 | v1 只承诺"上游输出直传"，复杂变换走 LLM 摘要步 |
| 范围膨胀 | 候选比较/迭代/条件分支/真并发全部后置 v2，不在本阶段 |
